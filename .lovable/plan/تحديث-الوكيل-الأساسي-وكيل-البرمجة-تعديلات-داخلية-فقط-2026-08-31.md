# تحديث الوكيل الأساسي + وكيل البرمجة (تعديلات داخلية فقط)

عملت فحص عميق للكود. ده الملخص وخطة التنفيذ. **مش هلمس أي ملف واجهة أمامية** — الشغل كله في `src/lib/*` (منطق)، `supabase/functions/*`، و `api/*`.

## اللي موجود دلوقتي

**الوكيل الأساسي (MEGSY chat)**
- البرومبت والسياق يتبنوا في العميل: `src/lib/modelSystemPrompts.ts`, `src/lib/chat/capabilities.ts`, `src/lib/chat/turnContext.ts`.
- الاستدعاء الفعلي والأدوات بتتنفذ في دالة `chat-alibaba` **الغير موجودة في الريبو** (منشورة خارجيًا).
- الأدوات مش JSON tool-schema — مجرد وصف نصي + وسوم زي `<CONNECT>` و `<MEGSY_MAIL>`.
- في نظام أدوات تاني منفصل تمامًا: `supabase/functions/_shared/agentkernel/tools.ts` (للمهام الطويلة) غير مربوط بالشات.

**وكيل البرمجة (Dev Agent)**
- `api/dev-agent.ts` → `src/lib/devagent/*`: حلقة Router → Planner → Coder → Verifier على VM من Freestyle.
- أدواته: `write_file`, `read_file`, `delete_file`, `list_dir`, `bash`, `build`, `done`.
- التحقق: `npm run build` + فحوص ثابتة + بوابة اكتمال. **مفيش تشغيل اختبارات ولا lint**.
- `computer-agent` و `long-run` وكلاء متصفح، مش برمجة.

## الناقص (أهم النقاط)

1. **مفيش حقن ملفات مشروع**: لا `AGENTS.md` ولا `.agents/skills/*` ولا أي قواعد بتتقري وقت التشغيل. حتى لو الريبو المستورد فيه قواعد، الوكيل بيتجاهلها.
2. **مفيش سجل مهارات (skills registry)** حقيقي — الـ `activeSkill` بيتمرر بس من غير تنفيذ محلي.
3. **بروتوكول أدوات هش**: `TOOL:/PATH:/BODY:/<<<END>>>` بيتفكّ بـ regex، وبيتقص عند 4 بلوكات فقط للرد الواحد.
4. **مفيش أداة بحث** (grep/ripgrep) ولا أداة `git` معروضة للنموذج.
5. **مفيش حلقة تحقق كاملة**: لا `tsc` منفصل، لا `eslint`، لا `vitest`.
6. **مفيش قصّ لنتائج الأدوات ولا للسياق** في المسار الكامل (`chat-fast` بس بيقص).
7. **ازدواجية**: استخراج ذاكرة بيتبعت مرتين لدالتين مختلفتين؛ وبرومبت شخصية MEGSY متكرر في مكانين مختلفين ومتباعدين.
8. **أمان**: CORS مفتوح `*` في `supabase/functions/computer-agent/index.ts`؛ أداة `bash` بدون أي قائمة مسارات مسموحة؛ مفاتيح Freestyle/GitHub مشتركة بين كل المستخدمين.

## خطة التنفيذ

### المرحلة 1 — طبقة سياق موحّدة (جديدة)
- `src/lib/agent/projectContext.ts`: يقرأ ويحقن وقت التشغيل — `AGENTS.md` من الريبو المستورد، أي `.agents/skills/*/SKILL.md`، و`README` مختصر — مع سقف أحرف وأولويات.
- `src/lib/agent/skills.ts`: سجل مهارات حقيقي (تحميل + مطابقة بالوصف + حقن الجسم في البرومبت عند الحاجة). يخدم الشات والـ dev agent مع بعض.

### المرحلة 2 — تقوية وكيل البرمجة
- إضافة أدوات: `search_files` (grep داخل الـ VM)، `git` (status/diff/log محدود)، `run_tests`.
- استبدال قصّ الـ 4 بلوكات بحد ديناميكي + fallback JSON tool-call parsing بجانب البروتوكول النصي.
- توسيع حلقة التحقق: `tsc --noEmit` → `eslint` → `build` → `vitest` (لو موجود)، مع إصلاح تلقائي محدود لكل مرحلة.
- قصّ نتائج الأدوات (stdout/build log) لآخر ~8KB قبل إرجاعها للنموذج.

### المرحلة 3 — تنظيف الوكيل الأساسي
- مصدر واحد لشخصية MEGSY يستهلكه `chat-fast` و`modelSystemPrompts` (مفيش نسختين).
- إزالة استدعاء استخراج الذاكرة المكرر (نُبقي `memory-extract` فقط).
- إضافة قصّ/تلخيص للمحادثات الطويلة قبل الإرسال في `streamChat.ts` (منطق فقط).
- تعريف الأدوات كـ schema منظمة في ملف واحد `src/lib/agent/toolSchemas.ts` بدل الوصف النثري، وتمريرها للباك اند.

### المرحلة 4 — أمان
- تقييد CORS في `supabase/functions/computer-agent/index.ts` لنفس قائمة الأصول المسموحة في `authenticateRequest`.
- قائمة منع للمسارات الحساسة في `bash`/`delete_file` (`.env`, `~/.ssh`, بيانات الاعتماد).
- منع النموذج من قراءة/طباعة متغيرات البيئة داخل الـ VM عبر قاعدة صريحة + فلتر.

## ملاحظات
- مفيش تعديل على أي مكوّن React أو CSS أو صفحة.
- `chat-alibaba` مش في الريبو، فالتعديلات هناك محدودة بما يتبعته من العميل (البرومبت، الأدوات، السياق).
